# MySANY 欧洲地区 Cookie 合规执行方案

> 文档版本：1.0  
> 日期：2026-09-30  
> 适用范围：欧洲经济区（EEA）、英国及瑞士版本的 MySANY APP、APP 内 WebView 与相关 H5 页面  
> 说明：本文用于产品与技术实施，不替代目标国家律师的正式法律意见。

## 1. 项目目标

在 MySANY 中建立统一的 Cookie 与类似追踪技术授权机制，满足以下目标：

1. 用户主动同意前，只运行严格必要技术。
2. 非必要 Cookie、SDK、广告标识和追踪脚本默认关闭。
3. 用户可选择“全部接受”“全部拒绝”或按类别管理偏好。
4. 拒绝非必要技术后，用户仍能使用登录、设备管理、售后服务等核心功能。
5. 用户可以在“我—设置—Cookie 设置”中随时修改或撤回授权。
6. 产品能够保存授权证据，并在用途或供应商发生实质变化时重新征求授权。

## 2. 核心合规原则

### 2.1 默认状态

| 类别 | 默认状态 | 是否需要用户同意 | 用户能否关闭 |
|---|---|---|---|
| 严格必要 | 开启 | 通常不需要 | 否 |
| 功能体验 | 关闭 | 需要 | 是 |
| 分析统计 | 关闭 | 原则上需要 | 是 |
| 广告营销 | 关闭 | 需要 | 是 |

严格必要类别只能包含提供用户明确请求的服务所必需的技术，例如登录会话、安全认证、负载均衡和保存隐私选择。不能因为某项 SDK 对业务有价值，就直接将其归入严格必要。

### 2.2 有效同意

- 同意必须通过用户的主动操作产生。
- 不使用预先勾选、默认开启、沉默、滑动页面或“继续使用即同意”。
- “全部接受”和“全部拒绝”在第一层具有同等可见性和相近操作成本。
- 不以同意非必要 Cookie 作为使用核心功能的条件。
- 撤回同意不得比作出同意更困难。

### 2.3 与协议更新的关系

用户服务协议、隐私政策和 Cookie 授权分别管理：

- 用户服务协议是服务合同条款，重大变更可要求重新确认；拒绝后可以终止使用服务。
- 隐私政策主要承担告知义务，不将所有个人信息处理统一包装成“同意”。
- Cookie 与追踪授权必须独立选择；拒绝非必要类别后仍允许进入 APP。

## 3. 产品流程

```text
启动 APP
  ↓
只初始化必要组件
  ↓
检查用户服务协议版本
  ↓
如需更新：同意后继续 / 拒绝则退出
  ↓
检查 Cookie 授权记录及结构版本
  ↓
无有效记录 → 展示 Cookie 授权底部弹窗
  ├─ 全部接受 → 初始化所有已声明类别 → 进入首页
  ├─ 全部拒绝 → 保持非必要组件关闭 → 进入首页
  └─ 管理偏好 → 按类别保存 → 只初始化已授权类别 → 进入首页
```

### 3.1 第一层授权弹窗

弹窗必须包含：

- 使用 Cookie 和类似技术的简要目的；
- 严格必要技术始终启用的说明；
- 拒绝不会影响核心功能的说明；
- “全部拒绝”“全部接受”两个同等样式的决策按钮；
- “Cookies 管理”入口，用于进入分类设置、政策说明和 Cookie 详情。

禁止在用户选择前初始化分析、营销等非必要 SDK。

### 3.2 偏好管理

偏好管理按以下类别展示：

| 类别 | 用途示例 | 典型技术 |
|---|---|---|
| 严格必要 | 登录、安全、风控、保存授权状态 | 会话 Cookie、安全令牌、CMP 状态 |
| 功能体验 | 语言、地区、地图、界面偏好 | 本地偏好、地图 SDK |
| 分析统计 | 功能使用、崩溃、性能分析 | 产品分析 SDK、崩溃分析 SDK |
| 广告营销 | 个性化广告、营销归因、广告衡量 | 广告 ID、归因 SDK、广告 SDK |

每类至少说明使用目的、数据类型、保存期限、第三方合作方和跨境传输情况。

每个分类提供“查看 Cookie 详情”入口，进入独立二级页面后列出该分类下全部已登记 Cookie 或类似标识的名称、提供方、技术类型、具体作用和保存期限。

### 3.3 设置入口

路径：`我 → 设置 → Cookie 设置`

设置页支持：

- 查看当前授权概况；
- 单独开启或关闭功能、分析和营销类别；
- 分别查看四个分类下的 Cookie 详情；
- 一键全部拒绝；
- 一键全部接受；
- 保存当前选择；
- 访问 Cookie 政策与第三方合作方清单。

撤回后立即停止对应类别的新数据采集，并触发可执行的 Cookie、SDK 实例标识和广告标识清理流程。

## 4. 技术架构

### 4.1 启动顺序

必须先运行 `ConsentManager`，再初始化非必要 SDK：

```text
ConsentManager
  → 必要网络、安全和登录组件
  → 读取本机/账号授权记录
  → 验证授权结构版本
  → 根据类别初始化允许的 SDK
  → 进入业务页面
```

禁止采用“先初始化 SDK，再调用关闭采集”的方式。部分 SDK 会在初始化瞬间读取设备标识或发起网络请求，因此应在初始化前完成拦截。

### 4.2 ConsentManager 职责

- 读取本机授权记录；
- 获取服务端下发的政策、供应商和授权结构版本；
- 判断是否需要重新征求授权；
- 向原生模块、WebView 和 H5 提供统一授权状态；
- 根据类别控制 SDK 初始化、暂停和销毁；
- 写入授权审计记录；
- 处理撤回、Cookie 清理和标识重置。

建议提供统一接口：

```text
getConsentState()
hasConsent(category)
updateConsent(choices, source)
subscribeConsentChange(callback)
clearCategoryData(category)
```

### 4.3 WebView 与 H5

- APP 与 WebView 使用同一份授权状态。
- 未授权前不注入统计或广告脚本。
- 对非必要第三方域名实施允许列表控制。
- WebView 不重复展示另一套 Cookie 横幅。
- 用户撤回后，清除相应 WebView Cookie、LocalStorage 项及 SDK 标识。
- H5 新增供应商时必须同步更新 APP 的供应商清单和授权版本。

### 4.4 SDK 分类台账

每个 SDK 必须登记以下字段：

| 字段 | 说明 |
|---|---|
| SDK/供应商名称 | 正式公司与产品名称 |
| 所属类别 | 必要、功能、分析或营销 |
| 处理目的 | 为什么需要该 SDK |
| 数据类型 | 设备信息、日志、位置、广告 ID 等 |
| 初始化条件 | 对应类别被授权后 |
| 停止方式 | 暂停、禁用或销毁实例 |
| 清理方式 | Cookie、缓存、实例 ID、广告 ID 处理 |
| 请求域名 | SDK 可能访问的全部域名 |
| 保存期限 | 客户端与服务端分别填写 |
| 处理地区 | EEA 内外及跨境保护措施 |

崩溃分析和性能分析默认归入“分析统计”。如果希望适用某一成员国的统计豁免，应由当地法务针对具体配置单独确认。

## 5. 授权记录设计

### 5.1 客户端原型数据

原型使用以下本地存储键：

```text
mysany.cookieConsent.v1
```

记录结构：

```json
{
  "schemaVersion": "1.0",
  "policyVersion": "2026.09",
  "vendorListVersion": "1.0",
  "region": "EEA",
  "action": "save_preferences",
  "choices": {
    "necessary": true,
    "functional": false,
    "analytics": true,
    "marketing": false
  },
  "timestamp": "2026-09-30T10:30:00.000Z"
}
```

### 5.2 正式服务端记录

正式版本建议每次变更新增审计记录，不覆盖历史记录。除上述字段外，可增加：

- `consentId`：授权记录唯一标识；
- `userId`：登录后绑定账号；
- `anonymousId`：登录前随机生成的匿名标识；
- `source`：首次弹窗、设置页、Web 等；
- `locale`：展示给用户的语言版本；
- `regionEvidence`：地区判断方式，不长期保存完整 IP；
- `proofHash`：授权文案与供应商清单快照摘要。

授权记录只用于合规证明和执行用户选择，不用于用户画像。

## 6. 版本与重新授权

分别维护：

- `termsVersion`：用户服务协议版本；
- `privacyNoticeVersion`：隐私政策版本；
- `consentSchemaVersion`：授权类别和用途结构版本；
- `vendorListVersion`：第三方合作方清单版本。

以下变化需要重新征求相关类别授权：

- 新增处理目的；
- 新增追踪类别；
- 新增广告、分析或归因 SDK；
- 供应商的数据用途发生重大变化；
- 保存期限明显延长；
- 原授权文案不能合理覆盖新的处理行为。

文字纠错、联系方式调整等非实质更新一般无需重新征求 Cookie 同意，但应保留版本记录。

## 7. 地区策略

推荐全球统一采用欧洲基线，技术与运营风险最低。

如仅对欧洲启用，可综合使用应用市场地区、账号注册国家、IP 对应国家和 SIM 国家码。不能只依赖系统语言。无法确定地区时默认应用欧洲模式。

用户进入欧洲且没有符合欧洲要求的有效授权时，应重新展示授权面板；已有更严格选择的，不应自动放宽。

## 8. iOS 与 Android

- iOS ATT 授权不能代替 Cookie/追踪授权。
- 先取得“广告营销”授权，再在确有必要时触发 ATT 系统弹窗。
- 用户允许营销 Cookie 但拒绝 ATT 时，仍不得访问受 ATT 限制的广告标识。
- Android 广告 ID、归因 SDK 和类似设备标识纳入“广告营销”。
- 相机、定位、蓝牙等系统权限在使用对应功能时单独申请，不与 Cookie 授权合并。

## 9. 撤回与数据清理

用户关闭某类别后应立即：

1. 停止该类别的新事件采集与上传；
2. 取消排队但尚未发送的相关事件；
3. 禁用或销毁对应 SDK；
4. 删除可以删除的非必要 Cookie 和本地存储；
5. 调用供应商提供的实例 ID 重置或退出接口；
6. 写入新的撤回审计记录。

撤回并不自动等于删除历史数据。用户的数据访问、删除和反对权通过独立的隐私权利流程处理。

## 11. 实施阶段

### 阶段一：盘点与分类

- 盘点 APP、WebView 和 H5 的 Cookie、SDK、域名、广告标识及本地存储。
- 由产品、技术、安全和法务完成类别判断。
- 输出正式供应商清单、数据流和保存期限。

### 阶段二：基础能力

- 开发 ConsentManager。
- 建立 SDK 注册表及按类别延迟初始化能力。
- 建立服务端授权审计接口。
- 完成 WebView 与原生状态同步。

### 阶段三：产品接入

- 接入首次授权底部弹窗。
- 接入设置页 Cookie 偏好管理。
- 接入 Cookie 政策与第三方合作方清单。
- 接入撤回后的清理和标识重置。

### 阶段四：验证与发布

- 通过抓包和自动化测试验证零预加载。
- 完成安全、隐私、无障碍和多语言验收。
- 先在内部与小流量欧洲用户中灰度，再逐步扩大。
- 每季度复核 SDK、域名、用途、供应商与保存期限。

## 12. 职责分工

| 角色 | 主要职责 |
|---|---|
| 产品 | 交互、文案、版本策略、需求验收 |
| 客户端 | ConsentManager、SDK 门控、清理与设置页 |
| Web/H5 | 脚本门控、Cookie 清理、状态同步 |
| 服务端 | 配置下发、授权记录、版本判断、审计查询 |
| 数据团队 | 事件分类、未授权事件阻断、数据保留策略 |
| 安全与隐私 | SDK 盘点、数据流、跨境与风险评估 |
| 欧洲法务 | 目标国家规则、文案与豁免条件确认 |
| QA | 抓包、状态组合、升级、离线与回归测试 |

## 13. 本次原型交付映射

- `cookie-consent.html`：以现有首页为背景展示首次 Cookie 授权底部弹窗；第一层提供全部接受、全部拒绝和 Cookies 管理入口。
- `mine.html`：在“我—设置”中新增“Cookie 设置”，支持分类开关、分类详情、保存、全部拒绝和全部接受。
- `assets/app.js`：登录后检查本地授权结构版本；无有效记录时进入 Cookie 授权流程。
- `home.html`：底部“我”入口连接至“我的”页面。
- 本地授权键：`mysany.cookieConsent.v1`，授权页面与设置页共享同一份状态。

原型中的供应商名称、保存期限和政策正文均为演示内容。正式上线前必须替换为实际数据处理情况，并完成欧洲目标市场的法务复核。
