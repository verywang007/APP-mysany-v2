# APP MySANY · 用户注销申请方案

> 入口：`我 → 设置 → 注销申请`
> 关联后管：`客户管理 → 注销申请管理`
> 方案基线：`sany-后管/客户管理-注销申请管理.html`、`sany-后管/客户管理-账户注销-方案.md`、`APP-mysany/mine.html`
> 当前状态：**已确认，HTML 交互原型已生成**
> 日期：2026-10-08

---

## 一、方案结论

将 APP 当前“注销账号 → 一次确认弹窗 → Toast 提交成功”的简化操作，升级为可查询、可校验、可撤销、可追踪的完整注销申请流程。

本方案默认与现有后管原型保持一致：

1. APP 自助申请按用户类型分流：**个体户**校验通过后由系统自动审核通过，直接进入 `冷静期 COOLING`；**含企业租户/代理商身份**的账号进入 `待审核 PENDING`，由后管人工审核。
2. 审核通过后进入默认 15 天的 `冷静期 COOLING`。
3. 待审核和冷静期内，用户均可主动撤销申请。
4. 冷静期结束后进入 `注销中 PROCESSING`，此时不可撤销且停止登录。
5. 注销完成后，个人信息按规则删除或匿名化；审计、授权等依法必须保留的数据不会被表述为“全部永久删除”。
6. APP 使用与后管完全一致的申请单号、状态、时间和驳回原因，避免两端口径不一致。

## 二、现状与问题

### 2.1 APP 当前能力

当前 `mine.html` 在设置页提供“注销账号”入口，点击后仅展示二次确认：

> 注销后账号数据将在 15 天后永久删除，且无法恢复。期间重新登录可撤销注销。

确认后仅提示“注销申请已提交”，没有真实的过程页面。

### 2.2 与后管能力的差距

| 缺口 | 当前 APP | 后管已具备/要求 |
| --- | --- | --- |
| 申请信息 | 无原因、无申请单 | 申请单号、原因、来源、时间、用户快照 |
| 前置校验 | 无 | 硬拦截、软提醒及校验结果 |
| 身份核验 | 无 | 需要可举证的用户确认凭证 |
| 状态 | 只有提交成功 | 待审核、冷静期、注销中、失败、已注销、已驳回、已撤销 |
| 进度查询 | 无 | 后管有完整执行进度与日志 |
| 用户撤销 | 仅文案提及登录撤销 | 后管支持待审核/冷静期撤销 |
| 驳回处理 | 无 | 后管要求用户可见驳回原因 |
| 数据说明 | 表述为“永久删除” | 实际为删除、匿名化和必要留存并存 |

### 2.3 本期目标

- 用户能在 APP 独立完成申请、身份验证、结果查询和撤销。
- 注销影响在提交前清晰、具体、可理解，不以模糊文案代替告知。
- 用户侧状态与后管状态实时一致。
- 对不能注销的情况给出原因和明确解决路径。
- 为审核、投诉、合规回溯保留协议版本、验证记录和关键操作日志。

### 2.4 本期不做

- 企业租户或组织主体整体注销。
- 冷静期结束后的账号恢复。
- 在 APP 展示后管内部操作人、IP、子任务技术报错等内部信息。
- 改造后管现有列表和审核交互。

## 三、信息架构与入口

### 3.1 入口命名

路径保持为：`我 → 设置 → 注销申请`。

将当前“注销账号”改为“注销申请”，原因是该操作并非点击后立即注销，而是经过审核、冷静期和异步执行。页面主按钮使用更明确的“申请注销账号”。

### 3.2 设置页入口展示

| 账号状态 | 入口右侧信息 | 点击后 |
| --- | --- | --- |
| `NORMAL` | 无 | 进入注销须知页 |
| `PENDING` | 待审核 | 进入申请进度页 |
| `COOLING` | 冷静期 · 剩余 N 天 | 进入申请进度页 |
| `REJECTED` | 上次申请已驳回 | 查看驳回原因，可重新申请 |
| `REVOKED` | 上次申请已撤销 | 查看记录，可重新申请 |
| `PROCESSING` | 注销中 | 进入只读进度页；账号会被强制退出 |
| `FAILED` | 处理异常 | 进入异常说明页或在登录时展示阻断页 |
| `CANCELLED` | 不再进入设置页 | 登录时提示账号已注销 |

设置页仍保留单一入口，不额外增加“注销进度”，避免同一功能出现两个入口。

## 四、用户主流程

```text
我 → 设置 → 注销申请
  → 注销须知与影响说明
  → 选择注销原因、内容处理方式并勾选协议
  → 前置校验
      ├─ 命中硬拦截：展示问题和解决入口，不允许提交
      └─ 校验通过/仅软提醒：展示将清零、解绑、匿名化的具体项目
  → 身份验证（手机号/邮箱/现有安全验证方式）
  → 最终确认
  → 提交成功，生成申请单号
      ├─ 个体户：系统自动审核通过，直接进入冷静期，展示截止时间和撤销按钮
      └─ 含企业租户/代理商身份：状态为待审核，由后管人工审核
          ├─ 驳回：APP 展示原因，可重新申请
          └─ 通过：进入冷静期，展示截止时间和撤销按钮
  → 冷静期届满
  → 注销中，不可撤销，账号停止登录
      ├─ 成功：已注销，通知用户
      └─ 失败：展示系统处理中/联系客服，由后管重试
```

原则：**先告知和校验，再身份验证，最后提交**。校验失败时不消耗用户验证码，也不生成后管申请单。

## 五、页面方案

### 5.1 页面 A：注销须知

标题：`注销申请`

首屏需明确区分“退出登录”和“注销账号”，并说明以下影响：

- 账号将永久停止登录，冷静期结束后无法恢复。
- 积分、星星及未使用权益将清零且不可找回。
- 客户、企业子账户及普通设备绑定关系将解除。
- 实名/企业认证信息将按规则删除，重新注册需重新认证。
- 个人资料将删除或匿名化；订单、维护、授权、审计等必须保留的记录会去标识化后保留。
- 圈子内容默认保留并将作者显示为“已注销用户”；用户可申请同时删除本人发布的内容。
- 已注销后，再使用原手机号/邮箱注册视为新账号，历史数据和权益不恢复。

页面字段：

1. `注销原因`，必选：
   - 不再使用 MySANY
   - 更换服务平台
   - 隐私或个人信息原因
   - 使用体验问题
   - 个人原因
   - 其他
2. `其他原因说明`：选择“其他”时必填，最多 200 字；其余原因可选填。
3. `我发布的圈子内容`：
   - 保留并匿名化（默认）
   - 申请删除
4. 协议勾选：`我已阅读并理解《账号注销须知》，知晓注销后的影响。`

底部按钮：`检查账号并继续`。未选择原因或未勾选协议时禁用。

协议勾选仅代表用户已阅读；在最终提交成功时，才写入正式注销确认记录，避免把中途退出误记为已申请。

### 5.2 页面 B：账号检查结果

标题：`账号检查`

检查过程显示加载态“正在检查账号状态…”，结果分为两类。

为方便原型评审，点击“检查账号并继续”后先展示检查结果选择器，可选择“检查通过”或六类硬拦截并查看对应导向。该选择器仅用于原型演示；正式产品由系统根据账号数据自动判定，不向用户提供结果选择。

#### 硬拦截

命中任意一项，不允许继续：

| 检查项 | 用户提示 | 建议操作 |
| --- | --- | --- |
| 是设备管理员 | 您是 N 台设备的管理员 | 去移交管理员权限 |
| 是组织唯一主账号 | 您是组织“XXX”的唯一管理员 | 去组织管理/联系客服 |
| 有进行中的异常申诉 | 您有 N 条申诉正在处理中 | 去查看申诉 |
| 有未完结订单或退款 | 您有 N 个订单尚未完成 | 去处理订单 |
| 账号被锁定 | 当前账号状态异常 | 联系客服 |
| 已有进行中的注销申请 | 请勿重复提交 | 查看申请进度 |

如果 APP 尚无对应业务落地页，操作按钮统一降级为“联系客服”，不能提供无效跳转。

#### 软提醒

软提醒允许继续，但必须逐项展示具体值：

- N 积分、N 颗星星将清零。
- N 个企业子账户或客户关系将解除关联。
- N 台普通绑定设备将解除关系。
- 实名/企业认证信息将被清除。
- N 条维护/服务记录将匿名化保留。
- 试点活动或其他账号权益将失效。

底部按钮：`继续注销`；次按钮：`暂不注销`。

### 5.3 页面 C：身份验证

标题：`验证身份`

默认使用账号当前已验证的登录方式：

- 手机号账号：向脱敏手机号发送验证码。
- 邮箱账号：向脱敏邮箱发送验证码。
- 仅企业/第三方登录账号：使用现有二次认证方式；若无可用方式，引导联系客服，不直接放行。

交互要求：

- 展示验证码去向，如 `+86 133****2180`。
- 重新发送倒计时 60 秒。
- 验证码有效期和错误次数由安全策略配置。
- 验证成功后签发短时有效的注销验证凭证；凭证过期需重新验证。
- 修改注销原因或返回时间过长时，提交前重新检查账号状态。

底部按钮：`验证并继续`。

### 5.4 页面 D：最终确认

标题：`确认提交注销申请`

集中展示：

- 当前账号：昵称、脱敏手机号/邮箱。
- 注销原因。
- 主要清理项目摘要。
- 审核说明：提交后由平台审核。
- 冷静期说明：审核通过后进入 15 天冷静期，具体截止时间以申请详情为准。
- 撤销边界：待审核和冷静期可撤销，进入注销处理后不可撤销。

按钮：

- 主按钮：红色 `确认提交`
- 次按钮：`再想想`

提交需防重复点击。相同幂等键重复请求只能生成一个申请单。

### 5.5 页面 E：提交成功

标题：`申请已提交`

展示：

- 状态：待审核。
- 申请单号，例如 `CAN-20261006-0018`。
- 提交时间。
- 说明：“审核结果将通过 APP 消息及账号绑定的联系方式通知您。”

按钮：`查看申请进度`；次按钮：`返回设置`。

### 5.6 页面 F：申请进度/详情

标题：`注销申请`

页面结构：

1. 状态卡：状态名称、说明、关键日期或倒计时。
2. 进度条：提交申请 → 审核 → 冷静期 → 注销处理 → 完成。
3. 申请信息：申请单号、申请时间、原因、内容处理方式。
4. 影响摘要：积分、设备、客户关系等提交时的校验快照。
5. 状态说明或驳回原因。
6. 底部操作区，根据状态动态展示。

各状态展示规则：

| 状态 | 用户主文案 | 关键展示 | 可用操作 |
| --- | --- | --- | --- |
| `PENDING` 待审核 | 申请已提交，正在等待审核 | 申请时间、单号 | 撤销申请 |
| `COOLING` 冷静期 | 申请已通过，将于 YYYY-MM-DD 后开始注销 | 剩余天数、截止时间 | 撤销申请 |
| `REJECTED` 已驳回 | 本次申请未通过 | 完整驳回原因、驳回时间 | 重新申请、联系客服 |
| `REVOKED` 已撤销 | 本次申请已撤销，账号可正常使用 | 撤销时间 | 重新申请 |
| `PROCESSING` 注销中 | 正在处理账号数据，请勿重复操作 | 开始时间 | 无；仅联系客服 |
| `FAILED` 处理异常 | 注销处理暂未完成，平台正在处理 | 对用户友好的错误说明 | 联系客服 |
| `CANCELLED` 已注销 | 账号已完成注销 | 完成时间 | 退出至登录页 |

不向用户展示后管的内部处理人、内部备注、IP、具体失败子任务和重试按钮。

### 5.7 撤销确认

待审核或冷静期点击“撤销申请”时，弹出二次确认：

> 撤销后，本次注销流程将终止，账号继续正常使用。如需注销，可重新提交申请。

按钮：`继续注销`、`确认撤销`。

撤销成功后展示结果页，并同步后管状态为 `REVOKED`。撤销操作必须记录时间、设备和操作来源。

## 六、登录与会话规则

| 状态 | 是否允许登录 | 登录后处理 |
| --- | --- | --- |
| `PENDING` | 是 | 首页轻提示“注销申请待审核”，可进入进度页 |
| `COOLING` | 是 | 登录后弹窗提示仍在冷静期；用户明确点击“撤销申请”才撤销，登录本身不自动撤销 |
| `REJECTED` / `REVOKED` | 是 | 正常登录；设置入口保留历史结果 |
| `PROCESSING` | 否 | 清理所有会话和推送 Token，展示“账号正在注销”阻断页 |
| `FAILED` | 否 | 展示“注销处理异常，平台正在处理”，提供客服入口 |
| `CANCELLED` | 否 | 展示“账号已注销”；可返回登录或注册新账号 |

冷静期登录弹窗按钮：

- 主按钮：`继续保留注销申请`，进入 APP，申请不变。
- 次按钮：`撤销注销申请`，再次确认后撤销。

这样可避免“只因登录一次就误撤销”的情况，也与后管可主动撤销的能力一致。

### 6.1 重新登录弹窗

用户退出 APP 后重新登录，首页读取后管同步的最新注销状态并展示对应弹窗：

| 状态 | 弹窗标题 | 操作 |
| --- | --- | --- |
| `PENDING` | 注销申请正在审核 | 继续使用、查看进度 |
| `COOLING` | 注销申请冷静期中 | 继续保留申请、撤销申请（二次确认） |
| `REJECTED` | 注销申请未通过 | 知道了、查看原因 |
| `REVOKED` | 注销申请已撤销 | 知道了、查看记录 |
| `PROCESSING` | 账号正在注销 | 返回登录、联系客服 |
| `FAILED` | 注销处理暂未完成 | 返回登录、联系客服 |
| `CANCELLED` | 账号已完成注销 | 返回登录 |

`PROCESSING`、`FAILED`、`CANCELLED` 弹窗不可关闭进入首页，以符合账号不可登录规则。弹窗仅在本次登录成功后触发，普通首页刷新不重复打扰。

## 七、与后管的状态及字段映射

### 7.1 状态映射

APP 不建立独立状态值，直接使用后管值集 `MYSANY.ACCOUNT_CANCEL_STATUS`：

`PENDING`、`COOLING`、`PROCESSING`、`FAILED`、`CANCELLED`、`REJECTED`、`REVOKED`。

`NORMAL` 代表当前无进行中的注销流程，不作为申请单状态展示。

### 7.2 申请字段

| APP 内容 | 后管/接口字段建议 | 说明 |
| --- | --- | --- |
| 申请单号 | `cancelApplyNo` | 提交成功后返回 |
| 用户ID | `userId` | 服务端从登录态获取，不信任客户端传值 |
| 申请来源 | `applySource=APP_SELF` | 后管展示“App自助” |
| 注销原因 | `cancelReason` | 枚举编码 |
| 补充说明 | `cancelReasonDesc` | 最多 200 字 |
| 内容处理方式 | `contentHandlingMode` | `ANONYMIZE` / `DELETE_REQUESTED`，需新增 |
| 检查结果 | `checkResult` | 提交时的结果快照 |
| 协议版本 | `agreementVersion` | 需新增，支持合规举证 |
| 确认时间 | `consentTime` | 需新增 |
| 验证方式 | `verifyMethod` | 只记录方式和结果，不保存验证码 |
| 申请时间 | `applyTime` | 以服务端时间为准 |
| 冷静期截止 | `coolingEndTime` | 后管审核通过后返回 |
| 驳回原因 | `auditOpinion` | APP 完整展示给用户 |
| 完成/失败时间 | `finishTime` | 状态详情展示 |

提交成功后同步写入隐私授权记录，建议类型为 `ACCOUNT_CANCELLATION_CONFIRM`，记录协议版本、语言、国家/地区、确认时间及申请单号。

### 7.3 接口能力建议

| 能力 | 建议语义 |
| --- | --- |
| 查询当前/最近申请 | 返回最新申请、可用操作和服务端时间 |
| 注销前检查 | 返回硬拦截、软提醒、展示文案和可跳转动作 |
| 发送/校验验证码 | 复用现有账号安全验证能力 |
| 提交申请 | 校验身份凭证和幂等键，创建 `PENDING` 申请 |
| 撤销申请 | 仅允许 `PENDING`、`COOLING`，服务端再次判断状态 |
| 查询申请详情 | 返回用户可见的状态、时间、原因和进度节点 |

客户端不根据本地时间自行判定冷静期结束，倒计时以服务端返回的 `serverTime` 和 `coolingEndTime` 为准。

## 八、前置校验与提交规则

1. 打开入口时先查询是否已有进行中的申请，有则直接进入进度页。
2. 前置校验结果只短时有效；最终提交时服务端必须再次校验。
3. 执行注销前，后端按既有方案再次执行校验，防止冷静期内账号状态变化。
4. APP 只展示用户能理解和处理的业务原因，不透出表名、字段名和内部异常堆栈。
5. 网络超时后先查询当前申请，再决定是否重试，防止重复申请。
6. 后管强制撤销后，APP 下次刷新立即显示 `REVOKED`。
7. 后管驳回必须提供用户可见原因；空原因不允许完成驳回。

## 九、通知方案

| 事件 | APP 站内消息/推送 | 短信或邮件 |
| --- | --- | --- |
| 提交成功 | 必须 | 建议 |
| 审核通过、进入冷静期 | 必须，含截止日期 | 必须 |
| 审核驳回 | 必须，含原因 | 建议 |
| 冷静期即将结束 | T-3 天、T-1 天 | T-1 天建议 |
| 用户/后管撤销 | 必须 | 建议 |
| 开始注销 | 必须 | 建议 |
| 注销完成 | 登录外渠道通知 | 必须 |
| 注销失败 | 登录外渠道通知 | 必须，提供客服方式 |

通知内容不展示完整手机号、邮箱、证件号、设备号等敏感信息。点击通知时，如账号仍可登录，进入申请详情；已不可登录时进入状态阻断页。

## 十、文案原则

### 10.1 禁止使用

- “15 天后所有数据永久删除”——与后管的匿名化和必要留存策略不一致。
- “登录即撤销”——容易造成误撤销，且用户没有明确表达撤销意愿。
- “注销失败，请重试”——执行重试属于后管能力，不应让用户重复提交。

### 10.2 推荐核心文案

注销须知：

> 注销完成后，您的账号将无法登录，积分和未使用权益将清零，设备及客户关系将解除。个人信息将依据适用规则删除或匿名化；为履行法定义务、解决争议或保障交易安全所必需的记录，将在限定期限内安全保存。

冷静期：

> 您的注销申请已通过，将于 {YYYY-MM-DD HH:mm} 后开始处理。在此之前您可以撤销；开始处理后将无法恢复。

注销中：

> 账号注销正在处理中，暂时无法登录。完成后我们将通过您绑定的联系方式通知您。

## 十一、安全、合规与埋点

### 11.1 安全与合规

- 提交和撤销均要求有效登录态，并校验 CSRF/设备风险。
- 身份验证凭证短时有效且只能用于当前账号的一次注销提交。
- 验证码、证件信息不写入客户端日志或埋点。
- 申请详情中的手机号、邮箱始终脱敏。
- 协议和告知内容需支持多语言及版本化；具体保留时限、冷静期按国家/地区配置，并以法务结论为准。
- 注销接口需幂等，关键操作进入不可编辑的审计日志。

### 11.2 建议埋点

| 事件 | 目的 |
| --- | --- |
| `cancel_entry_view` | 入口访问量 |
| `cancel_notice_continue` | 须知页继续率 |
| `cancel_precheck_blocked` | 各硬拦截原因分布 |
| `cancel_precheck_passed` | 校验通过率 |
| `cancel_verify_result` | 身份验证成功/失败率 |
| `cancel_submit_result` | 提交成功率及失败原因 |
| `cancel_progress_view` | 进度页访问量 |
| `cancel_revoke_result` | 撤销率及所处状态 |
| `cancel_support_click` | 客服介入需求 |

埋点只记录原因编码、状态和结果，不上传用户填写的自由文本及联系方式。

## 十二、异常场景

| 场景 | 处理 |
| --- | --- |
| 检查或提交时断网 | 保留用户已选原因；恢复后重新检查，不提示已提交 |
| 提交超时但服务端已成功 | 查询当前申请并进入成功/进度页，不重复创建 |
| 验证码过期或错误过多 | 按账号安全策略提示稍后重试或联系客服 |
| 校验后账号状态变化 | 最终提交返回最新阻断原因，并回到检查结果页 |
| 审核期间被后管驳回/撤销 | APP 刷新后立即展示最新状态和原因 |
| 冷静期结束时又产生硬拦截 | 不直接误注销；进入异常处理，由后管处理并通知用户 |
| 注销执行部分失败 | 账号保持不可登录；由后管重试，用户不得重复申请 |
| 多设备同时撤销 | 首次成功后其余请求返回最新 `REVOKED` 状态 |

## 十三、原型改造范围

已新增 `APP-mysany/account-cancellation.html` 与 `assets/cancellation.css`，并在 `mine.html` 设置页接入“注销申请”入口。

原型已覆盖：

1. 设置页将“注销账号”改为“注销申请”，支持状态摘要。
2. 注销须知、原因选择、协议勾选。
3. 前置检查结果，演示“校验通过 + 4 条软提醒”。
4. 验证码身份验证和最终确认。
5. 提交成功与待审核详情。
6. 冷静期倒计时和撤销交互。
7. 已驳回、注销中、注销失败的状态展示。
8. 支持 URL 直达相关页面，便于评审不同状态。
9. APP 申请写入共享原型状态，后管注销申请管理可读取并处理同一申请单。
10. 后管审核、驳回、撤销和重试结果实时回写 APP。
11. 退出后重新登录，首页按最新状态展示注销提示弹窗。

原型视觉继续沿用当前 APP 的白底、灰色卡片、圆角列表及底部固定操作区，不引入新的视觉体系。

## 十四、验收标准

1. `我 → 设置 → 注销申请` 可完成从告知到提交的完整链路。
2. 未勾选协议、未选择原因或身份验证未通过时不能提交。
3. 硬拦截命中时不能进入身份验证；软提醒确认后可继续。
4. 成功提交后 APP 与后管均出现同一申请单号；个体户初始状态为 `COOLING`（系统自动审核通过），含企业租户/代理商身份的初始状态为 `PENDING`。
5. 后管审核、驳回、强制撤销后，APP 在刷新或重进页面时展示一致结果。
6. `PENDING`、`COOLING` 可撤销；其他状态服务端拒绝撤销。
7. 冷静期展示服务端计算的准确截止时间，不写死客户端 15 天。
8. `PROCESSING`、`FAILED`、`CANCELLED` 阻止登录并展示对应说明。
9. 用户侧不出现后管内部备注、处理人、IP、技术失败详情。
10. 不再出现“全部数据永久删除”或“登录自动撤销”的不准确文案。

## 十五、待确认项

| # | 待确认项 | 本方案建议 |
| --- | --- | --- |
| 1 | APP 自助申请是否必须人工审核 | **按用户类型分流**：个体户免人工审核，校验通过后系统自动审核通过直接进入 `COOLING`；含企业租户/代理商身份的账号仍由后管人工审核，提交后进入 `PENDING` |
| 2 | 冷静期是否固定 15 天 | 原型先展示 15 天；产品按国家/地区配置，APP 读取后端截止时间 |
| 3 | 冷静期登录是否自动撤销 | **不自动撤销**，由用户明确点击“撤销注销申请” |
| 4 | 圈子内容默认处理方式 | 默认保留并匿名化，同时提供“申请删除”选项 |
| 5 | 注销身份核验方式 | 优先复用手机号/邮箱验证码；无可用安全方式时转人工客服 |
| 6 | 待审核阶段是否允许用户撤销 | **允许**，与既有状态机定义一致 |
| 7 | 设置页入口名称 | 使用“注销申请”，页面主操作使用“申请注销账号” |

如无调整，可按以上建议作为后续原型基线。
