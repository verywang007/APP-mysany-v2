# 个性化推荐需求文档

版本：V1.0  
日期：2026年11月5日  
状态：产品评审稿

## 1 需求概述
数据处理核心规则：
1. 已授权个性化推荐时，可以为推荐收集用户ID和设备ID，并在授权范围内开展针对具体用户或设备的分析。
2. 未授权时，推荐及分析链路不收集用户ID和设备ID；如确需使用匿名数据，必须将用户ID／设备ID做不可逆的匿名化（例如加盐哈希并满足第 7.2 节全部约束），且不做针对具体用户或设备的分析，仅开展不能定位到具体用户或设备的汇总分析。


## 3 用户与场景

| 用户状态 | 场景 | 预期行为 |
| --- | --- | --- |
| 新安装用户 | 首次启动 | 展示推荐授权弹窗，选择前不启动个性化采集 |
| 已授权用户 | 浏览产品、资讯 | 可收集推荐所需用户ID、设备ID及已告知行为数据 |
| 拒绝用户 | 浏览产品、资讯 | 提供通用内容，不按具体用户或设备分析 |
| 已授权用户 | 隐私设置关闭推荐 | 停止后续个性化采集和分析，切换通用内容 |
| 未授权用户 | 隐私设置开启推荐 | 保存主动授权后启用，不补采未授权期间历史行为 |

## 5 功能需求

### 5.1 入口

| 入口 | 路径 | 进入后状态 |
| --- | --- | --- |
| 首次启动 | 新下载 APP 首次打开，参考 `/#/ads` | 必要协议流程完成后展示；不得与其他弹窗重叠 |
| 主动管理 | 我 → 设置 → 隐私设置 → 个性化推荐 | 展示当前有效授权状态，无有效授权时关闭 |

### 5.2 首次授权弹窗

| 元素 | 文案或要求 |
| --- | --- |
| 标题 | “MySANY”个性化推荐 |
| 说明 | 根据您的浏览记录，为您推荐相关产品及资讯信息 |
| 不同意按钮 | 不允许 |
| 同意按钮 | 允许 |
| 样式 | 沿用 ads 原型居中浅灰半透明圆角面板，左对齐文案，两个并列按钮 |

用户点击“允许”前，不得初始化会自动采集用户ID或设备ID的推荐SDK。关闭蒙层、返回、异常退出不得等同允许，未选择时按未授权处理。
选择后关闭弹窗并继续使用 APP；拒绝后不在每次启动时重复询问，用户可在设置中主动开启。

### 5.3 隐私设置开关

| 元素 | 内容 |
| --- | --- |
| 名称 | 个性化推荐 |
| 副标题 | 根据您的浏览记录，为您推荐相关产品及资讯信息 |
| 开启条件 | 已取得有效授权 |
| 默认状态 | 关闭；不得因同意隐私政策或登录而自动开启 |
| 开启成功提示 | 已开启个性化推荐 |
| 关闭成功提示 | 已关闭个性化推荐 |
| 保存失败提示 | 设置保存失败，请重试 |

开启：用户主动操作后保存授权，成功后启动个性化推荐。请求未完成前禁用重复操作，不提前采集。

关闭：立即停止客户端相关采集，并提交撤回记录；后续内容使用通用推荐。
### 5.4 授权后的内容表现

允许后可以使用授权后产生的行为，结合用户ID和设备ID进行推荐分析。用户未登录时 userId 为空，不得为填充该字段额外生成替代用户身份。

未授权时正常提供最新、热门、栏目等通用内容。


## 6 术语与概念

| 概念 | 说明 |
| --- | --- |
| 个性化推荐 | 根据具体用户或设备的浏览等行为，推荐产品及资讯 |
| 通用推荐 | 不基于具体用户或设备画像的热门、最新等内容 |
| 用户ID | 可关联到账号的标识，字段建议为 userId |
| 设备ID | 可关联到设备或安装实例的标识，字段建议为 deviceId；包括第三方SDK生成的同类标识 |
| 未授权 | 尚未选择、拒绝、已撤回、记录缺失或无法确认有效授权 |
| 去标识化 | 使用替代值隐藏原标识；仍可能关联同一主体，不能直接当作匿名化 |
| 匿名化 | 无法识别或关联具体用户、设备，且无法恢复关联的数据处理结果 |
| 授权记录 | 用户允许、拒绝或撤回的事实，独立于推荐行为数据保存 |


## 7 数据规则

### 7.1 采集与分析矩阵

| 数据或行为 | 已授权 | 未授权 |
| --- | --- | --- |
| 用户ID | 可按推荐所需采集 | 推荐与分析链路不采集、不传输、不落库 |
| 设备ID | 可按推荐所需采集 | 推荐与分析链路不采集、不传输、不落库 |
| 可稳定关联主体的哈希ID | 按授权范围控制 | 禁止用于个体分析，不能当作匿名数据绕过授权 |
| 浏览等行为 | 按已告知范围采集并关联主体 | 仅可进入经过验证、不能关联主体的匿名汇总链路 |
| 用户或设备画像 | 可基于有效授权数据构建 | 不新增、不更新、不读取用于推荐 |
| 通用内容 | 可提供 | 必须可提供 |
| 授权前历史行为 | 不因后续授权而补采或回填 | 不缓存等待日后补传 |

以上“不采集”包括事件正文、请求参数、Header、URL、公共埋点字段、SDK默认字段、代理日志及异常日志中的推荐用途标识。

### 7.2 匿名化方案约束

本期默认在采集源头移除用户ID和设备ID。若采用匿名化（例如加盐哈希），需同时满足：

1. 在数据进入推荐或分析链路前完成处理，不能先上传明文再由分析端隐藏。
2. 不保存原始ID与匿名结果的映射，不生成跨会话、跨设备可复用的稳定主体键。
3. 不通过共同盐值、请求上下文、账号信息或其他数据恢复主体关联。
4. 汇总输出不支持下钻到单个用户或设备，不计算按稳定主体去重的用户数、留存、个人漏斗及跨会话轨迹。
5. 验证日志、队列、备份和第三方SDK均不存在残留关联字段；验证不通过时停用该匿名化链路。

匿名统计可采用时间段、内容类别等维度的汇总次数；小样本维度应合并或抑制输出，阈值由数据评审明确。单纯加盐哈希不视为满足以上条件。

### 7.4 多端与异常同步

建议登录后以账号授权服务为准，本机缓存辅助控制；有效状态未确认前按未授权处理。切换账号先停止原账号采集，再读取新账号状态。

服务端对每次个性化采集与分析任务校验当前授权，客户端缓存允许不能覆盖服务端已撤回。请求中携带授权版本，旧版本请求不得覆盖新版本状态。

未登录首次允许与登录后账号状态如何合并、跨设备生效方式需要评审确认；规则未落定前，不自动扩大授权范围。

### 7.5 撤回与历史数据

撤回后取消待发送的个性化事件，清除本机未上报队列和与该目的相关的推荐缓存。服务端拦截撤回后到达的个性化事件，暂停相关画像更新、个体分析和推荐读取。

撤回前已合法产生的数据不再继续用于该用户或设备的个性化推荐。历史数据删除、不可逆匿名化及备份清理时限由数据负责人评审确定，正式上线前须补齐；不得以“历史数据”为由持续更新或使用个体画像。

清除缓存和重装 APP 不等于自动授权；无有效记录时回到未授权。已保存的拒绝记录不得被版本升级默认改为允许。

## 9 验收标准

| 编号 | 验证场景 | 预期结果与验证方式 |
| --- | --- | --- |
| P01 | 新安装首次打开、未选择 | 弹窗文案正确；抓包及日志无推荐用途用户ID、设备ID |
| P02 | 点击允许 | 保存成功后才启用采集；开关同步开启 |
| P03 | 点击不允许 | 正常进入通用内容； |
| P04 | 拒绝后重新启动 | 不重复弹出，不自动开启 |
| P05 | 隐私设置页开启 | 从该授权成功时点采集 |
| P06 | 设置页关闭 | 本机立即停采，服务端撤回后拒绝旧版本上报 |
| P08 | 拒绝期间浏览后再允许 | 不补传此前行为，不回填此前主体轨迹 |
| P09 | 检查匿名数据 | 无明文或稳定哈希主体键，无映射，可用维度不能恢复主体 |
| P10 | 替代ID检查 | 不通过广告ID、安装ID、令牌或指纹绕过授权 |
| P12 | 切换账号、多端撤回 | 状态隔离，旧授权不能覆盖新撤回 |
| P13 | 并发点击及旧请求重放 | 不生成互相覆盖的错误状态，状态版本校验有效 |
| P14 | 查看分析报表 | 未授权数据不能下钻到个人或设备，不用于个体留存和画像 |

## 10 评审确认项

1. 确认本期采用源头不采集ID方案；如启用加盐哈希等匿名化，指定验证负责人和通过标准。
2. 确认未登录到登录的授权合并规则及跨设备生效机制。
3. 明确历史推荐数据、画像、队列及备份的删除或匿名化时限。
4. 确认推荐开关与现有Cookie广告营销字段的拆分及迁移方案。
5. 确认个性化行为字段清单、第三方SDK清单及匿名统计小样本阈值。
