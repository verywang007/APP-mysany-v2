# 隐私设置与用户头像授权需求文档

版本：V1.0  
日期：2026年11月5日  
状态：产品评审稿

## 1 需求概述

本次统一 MySANY 设置中的功能顺序与隐私管理入口，并补齐个性化推荐和个人头像展示的授权闭环。用户可在首次使用相关功能时选择授权，也可通过“我 → 设置 → 隐私设置”查看和修改选择。拒绝可选授权后，仍可使用基础功能。

本文依据现有原型与本次沟通整理。入口调整、跨页面授权同步及拒绝后的处理属于本次目标需求，不代表当前原型已全部实现。下文标记“建议”的规则需在评审时确认。

## 2 原型范围

| 原型 | 用途 |
| --- | --- |
| `/#/mine` | 我的、设置、隐私设置及账号相关入口 |
| `/#/ads` | 新下载 APP 首次打开时的个性化推荐授权弹窗及样式参考 |
| `/#/home?avatarConsent=1` | 用户头像授权独立演示，可切换评论和发帖场景 |
| `/#/home` | 帖子浏览、评论和发帖的真实触发入口 |

弹窗采用 ads 原型中的居中系统提示样式：浅灰半透明面板、圆角、左对齐标题和说明、底部两个并列按钮。首页底部不再显示隐私政策及用户服务协议入口。

## 3 设置入口与排序

### 3.1 统一入口

主路径为“底部我 → 右上角设置 → 隐私设置”。建议移除“我的”页面功能列表中重复的隐私设置入口，保留设置页中的唯一入口。通过返回按钮逐级返回，保留上一页浏览位置。

### 3.2 设置页面顺序

| 顺序 | 功能 | 展示与交互 |
| --- | --- | --- |
| 1 | 语言 | 显示当前语言，点击选择 |
| 2 | 隐私设置 | 进入统一的隐私管理页面 |
| 3 | 使用帮助 | 进入帮助页面 |
| 4 | 服务电话 | 展示号码和服务时间，点击发起拨号 |
| 5 | 清除缓存 | 展示清理结果；不得清除授权记录 |
| 6 | 当前版本 | 展示版本，点击检查更新 |
| 7 | 注销申请 | 独立分组置于列表底部；有申请时展示状态 |
| 底部固定 | 切换租户 | 保留现有切换流程 |
| 底部固定 | 退出登录 | 二次确认后退出 |

上述为建议排序：将日常操作前置，将注销申请与一般设置分组。不得修改现有注销审核流程。

### 3.3 隐私设置页面顺序

| 顺序 | 功能 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | 消息推送 | 开关 | 沿用现有推送控制逻辑 |
| 2 | 个性化推荐 | 开关及说明 | 根据您的浏览记录，为您推荐相关产品及资讯信息 |
| 3 | 展示个人头像 | 开关及说明 | 在组织管理、圈子等公开场合展示个人头像 |
| 4 | 强制解除提醒 | 开关 | 沿用现有业务规则 |
| 5 | 隐私政策 | 页面入口 | 查看全文 |
| 6 | 用户服务协议 | 页面入口 | 查看全文 |

隐私设置中的开关与相应授权弹窗必须读取同一份记录。展示头像指公开展示权限，不等于修改头像，也不等于授权相机或相册。

## 4 个性化推荐授权

### 4.1 触发条件

新下载 APP 后首次打开，在启动流程中展示个性化推荐授权弹窗。建议在必要的协议流程完成后展示，避免多个弹窗重叠。用户尚未作出选择时，不启用个性化推荐。

| 元素 | 文案 |
| --- | --- |
| 标题 | “MySANY”个性化推荐 |
| 说明 | 根据您的浏览记录，为您推荐相关产品及资讯信息 |
| 左按钮 | 不允许 |
| 右按钮 | 允许 |

### 4.2 选择结果

允许：保存授权，隐私设置中的个性化推荐开关开启，进入后续页面。

不允许：保存拒绝选择，开关关闭，继续启动；提供通用产品及资讯内容。建议后续启动不重复询问，用户可主动在隐私设置开启。

本弹窗为应用内业务授权提示，不替代操作系统要求的权限流程。本文不新增操作系统权限申请。

### 4.3 撤回与记录

在隐私设置关闭个性化推荐后，停止后续依赖该授权的推荐处理；再次开启时更新授权记录。现有原型将该开关与 Cookie 的“广告营销”类别联动，建议保留单一数据来源并明确同步边界，避免一个入口关闭而另一个仍开启。

## 5 用户头像展示授权

### 5.1 触发条件

用户首次在帖子详情填写评论并点击“发送”，或首次完成帖子内容并点击“发布”时，先完成内容校验，再判断头像授权状态。未选择状态触发授权弹窗，不得在授权选择前提交内容。

| 元素 | 文案 |
| --- | --- |
| 标题 | 展示个人头像 |
| 副标题 | 在组织管理、圈子等公开场合展示个人头像 |
| 左按钮 | 暂不授权 |
| 右按钮 | 同意授权 |

点击蒙层不提交、不默认同意。建议返回键按“暂不授权”处理，保留草稿。

### 5.2 同意授权

保存个人头像展示授权，隐私设置开关同步开启，并继续执行刚才的评论或发布操作。只允许提交一次，防止连续点击导致重复评论或重复发帖。提交成功后更新列表和计数；提交失败保留草稿，授权结果不回滚。

### 5.3 暂不授权

与现有演示保持一致：关闭弹窗，中止本次发送，保留已填写的内容及媒体，允许用户继续编辑或返回。不得显示“发送成功”。建议再次点击发送时重新申请授权，用户也可前往隐私设置主动开启。

### 5.4 两种触发场景共用授权

建议评论与发帖共用一项“展示个人头像”授权。任一场景同意后，另一个场景不再重复申请。独立演示页可分别重放两个触发场景，但不能因此形成两份互相独立的正式授权。

当前原型分别保存评论和发帖授权，而隐私设置另有 showAvatar 字段；研发应将三处合并，消除状态不一致。

### 5.5 撤回后的行为

用户关闭隐私设置中的“展示个人头像”后，停止在组织管理、圈子、帖子与评论等公开位置展示其自定义头像，使用系统默认头像；个人资料页仍可管理本人头像。建议历史内容也按当前展示权限渲染，不要求删除帖子或评论。

撤回后再次评论或发布，重新展示授权弹窗；拒绝时按本节的保留草稿规则处理。开启开关即视为用户主动授权，无须再次弹出相同确认。

## 6 授权状态与保存规则

| 状态 | 开关显示 | 自动触发行为 |
| --- | --- | --- |
| 未选择 | 关闭 | 到达对应首次触发点时询问 |
| 已授权 | 开启 | 直接执行后续操作 |
| 已拒绝 | 关闭 | 推荐启动不重复询问；头像再次发送时询问 |
| 已撤回 | 关闭 | 推荐保留关闭；头像再次发送时询问 |

建议登录后以账号授权记录为准，跨设备同步；首次启动未登录时以本机选择暂存，登录合并规则需评审确认。切换账号不能沿用前一个账号的头像授权；切换租户建议沿用同账号选择。清缓存、退出登录不应被当作撤回授权。

记录至少包含授权类型、结果、触发来源、授权文案版本和操作时间。页面进入、修改及提交前读取最新状态；保存失败提示重试，界面不得表现为已成功保存。

| 编号 | 验证场景 | 预期结果 |

| A05 | 在隐私设置修改推荐开关 | 授权记录与推荐行为同步 |

## 9 评审确认项

1. 确认设置页建议顺序及移除我的页面重复隐私设置入口。
2. 确认评论、发帖共用一项头像展示授权，替换当前原型的两份记录。
3. 确认拒绝头像授权时中止发送并保留草稿，而不是以默认头像直接发送。
4. 确认撤回后历史内容的头像展示范围，以及账号跨设备、未登录到登录的记录合并规则。
5. 确认首次启动推荐弹窗与协议流程的先后顺序，以及 Cookie 广告营销的联动边界。
